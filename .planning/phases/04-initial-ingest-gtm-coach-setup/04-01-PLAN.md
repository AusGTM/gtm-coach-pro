A first-time setup binds Google Drive as a `drive_folder` source (Step 2, Phase 1 already resolves
`root_folder_id`). Step 4 loops `recording_sources[]`, hits the `drive_folder` entry, and reads
`drive-source.md`. It lists notes docs by the `Notes by Gemini` title pattern scoped to the resolved
folder, bounded to the last 90 days — a doc dated `2026/03/10` (>90 days before a 2026/07/24 setup)
is skipped; `Acme <> Vendor sync - 2026/07/18 Notes by Gemini` is in-window. For that doc,
`drive-source.md` runs: export → semantic-role parse (Summary → `## Summary`, Next-steps →
`## Commitments & next steps`) → pair the transcript in the same subfolder → tag the transcript
verbatim and the notes prose paraphrase. Step 4 then hands the resulting SPICED call record to the
SHARED write path: it writes `calls/2026-07-18_acme-vendor-sync.md` (id = the notes-doc file id per
`memory-bank.md` dedup), upserts the deal/account/people, updates `index.json.calls[]` with
`source: google-drive` + `notes_doc_id`/`transcript_doc_id`/`drive_folder_id` + `has_transcript: true`,
refreshes `patterns/*.md`, and sets that source's `last_sync`. If the same bank also had a tl;dv
`api` source, the loop's other iteration ingests it through the identical write path — same
`index.json` shape, no Drive-specific fork.
