<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Drive MCP tool → local `sales-memory/` | Customer conversation data (Gemini notes/transcripts) crosses from Google Drive into local storage during incremental/backfill sync. |
| Drive folder scope → listing query | The sync's Drive `list`/`search` must stay scoped to the resolved recordings folder, not all of Drive. |
| Config identity → dedup | The dedup key (`notes_doc_id`) determines whether a re-synced doc is one record or a duplicate/merge. |
| Live source ↔ demo bank | A synthetic demo bank has no live source; syncing it must be refused. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Information Disclosure | Drive listing scope in Incremental/Backfill | medium | mitigate | Drive listing scoped to `root_folder_id`/`legacy_folder_id` only (mcp-discovery.md §4 / memory-bank.md privacy: reads never broadened to all of Drive). Task 1/2 keep listing folder-scoped. |
| T-05-02 | Tampering (data integrity) | Dedup on re-sync of an edited notes doc | medium | mitigate | Dedup keyed on `notes_doc_id` per memory-bank.md; a changed `modifiedTime` updates the same call record in place, never a synthesized-key duplicate or a merge (Task 1). |
| T-05-03 | Denial of Service | Un-paced backfill vs Drive per-user quota | medium | mitigate | Batch + exponential backoff on 403/429 + resumable cursor, reusing mcp-discovery.md §6 (Task 2); a rate-limit stalls one source, resumes from cursor, never fails the whole sync. |
| T-05-04 | Spoofing (provenance) | verbatim-vs-paraphrase tagging | low | accept | Provenance contract is owned by drive-source.md (Phase 2) and reused unchanged; sync does not alter it — the drive_folder branch calls the same procedure. |
| T-05-05 | Tampering | Sync run against a demo bank | low | mitigate | Existing `config.json.demo_mode` guard preserved (Preconditions, Task 1) — refuses to sync a synthetic bank. |
| T-05-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs in this phase — markdown-only skill edit, no dependency changes; supply-chain surface unchanged. |

No high/critical threats; `security_block_on: high` → no blocking human checkpoint required.
</threat_model>
