<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Existing v1 `config.json` → migrated v2 shape | an in-place migration that mis-maps fields can silently drop an existing source's `tool_map` or consent scope |
| Folder-resolution name search → resolved `root_folder_id` | resolving to the wrong or a too-broad folder controls what Drive content is later read |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03 | Tampering | config migration on read (Task 2) | medium | mitigate | Additive wrap of the singular shape into `recording_sources[]`, persisted once, preserving existing `tool_map` and optional tool fields; idempotent on an already-v2 config |
| T-01-05 | Information Disclosure | folder resolution (Task 1) | medium | mitigate | Resolution targets only the known Meet-notes candidate folders and records the resolved `root_folder_id`; it does not broaden to "search all of Drive" (broadening is scoped out in Plan 03's read-scope note) |
| T-01-SC | Tampering | package installs | n/a | accept | No npm/pip/cargo installs — markdown edits only; Package Legitimacy Gate N/A |
</threat_model>
