<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Google Drive documents → local `sales-memory/` bank | raw Google Docs can carry third-party inline comments and non-buyer speaker names the API-source consent flow never covered |
| Existing consented bank → newly bound Drive source | consent granted for tl;dv does not imply consent to ingest Google Drive content |
| gtm-coach setup branch → downstream ingest | the `source_kind` branch is the single seam; a leak of Drive-specific handling into skill logic would break tool-agnosticism |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02 | Repudiation / Information Disclosure | privacy-gate re-surface (Task 2, Step 3) | high | mitigate | Re-surface Drive-scoped consent before any Drive ingest when a Drive source is added to an already-consented bank; record the added source in PRIVACY.md |
| T-01-01 | Information Disclosure | Drive read scope (Task 2, memory-bank note) | high | mitigate | Scope Drive reads strictly to the resolved recordings folder; never broaden to all of Drive |
| T-01-04 | Information Disclosure | redaction scope (Task 2, memory-bank note) | medium | mitigate | Extend `redaction: on` to inline Doc comments/suggestions and non-buying-committee speaker names, not just emails/phone numbers |
| T-01-06 | Elevation of Privilege | source_kind branch (Task 1) | low | mitigate | Bind Drive by probed capability persisted to `tool_map`; no literal Drive tool method as a required key in skill logic |
| T-01-SC | Tampering | package installs | n/a | accept | No npm/pip/cargo installs — markdown edits only; Package Legitimacy Gate N/A |
</threat_model>
